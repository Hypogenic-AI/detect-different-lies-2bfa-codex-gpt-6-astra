## Integration guidance
Keep the fresh root uv environment for data preparation. Do not run dependency installers blindly across repositories: their numpy/datasets/torch constraints conflict. Adapt the small detector functions and local generation interface into experiment code, then `uv add` compatible dependencies after selecting CUDA/Transformers versions. No conda was used, despite SEP’s historical instructions. Original SEP model allowlist lacks Qwen2.5: add a tested local wrapper/chat template rather than merely changing the model string. Its published Llama2 checkpoint is not compatible with Qwen.

A6000 GPU with 49,140MiB total memory was visible during resource gathering. A 7B BF16 model should be a feasible pilot, subject to actual context/batch activation memory; 70B full precision is outside this single-card setup. Root Python is3.12.8. Generation/entailment weights have not been downloaded; they are experiment dependencies. Model candidate: [Qwen2.5-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct), Apache2 model card, open access; pin revision before running.

Important calibration nuance: Cooney Appendix E reports a historical pooled-token discrepancy. Current pinned Apollo `PromptScorer.prompt_score_threshold` uses per-response reduction, while `ReLUPromptScorer` also computes a separate token-level ReLU offset. These are different operations. We inspected code but did not reproduce the published correction; do not label every token quantile a bug. Record scorer/config and calibrate the final response score.

Shallow clones still contain substantial bundled data (~253MB Apollo, ~990MB Liars’ Bench before submodule). They remain in original repository layout for reproducibility and are not counted as separately curated datasets.
